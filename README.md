# Knowlogue
一个融合了个人知识管理、博客分享、社区实时交流的综合性平台。(初学，持续更新中~）

一、核心定位与差异化

定位：并非与WordPress、知乎、Notion等巨头正面竞争，而是专注于一个细分市场：“为小团队、社群、知识爱好者提供的、开箱即用的、一体化知识互动平台”。

目标用户：

（1）个体用户：希望有一个统一的平台管理自己的技术笔记和与同行交流

（2）研究小组：需要共享阅读笔记、资源并进行线上讨论。

（3）初创团队：用于内部知识Wiki、产品设计讨论和团队文化建设，替代零散的文档工具+IM软件组合。

口号：不止是博客，更是你的知识会客厅。	   构建你的知识宇宙：记录、分享、碰撞

优势在于功能的深度融合和部署的灵活性。本产品卖的不是单一功能，而是一个开箱即用的完整解决方案，特别适合那些既想要沉淀知识，又希望有一个活跃互动社区的群体，如：技术社群、读书会、研究小组、初创团队。
即使技术栈不是最新的，但独特的产品理念和极致的用户体验永远是本产品最大的竞争力。

1.1功能上的创新与竞争点

1.1.1强化知识管理与连接

双链笔记功能：让文章支持 [[文章名]] 语法进行内部链接，并自动生成“反向链接”面板。这是现代知识管理（如Obsidian）的核心功能，能极大提升知识库的价值。

全局知识图谱可视化：提供一个独立页面，以节点和连线的形式可视化全站所有文章和标签的关联关系，让用户直观地发现知识之间的联系。

内容块嵌入与引用：允许用户在一篇文章中直接引用另一篇文章的某一段落（块），并保持同步更新。

1.1.2增强社区互动与粘性

“知识派对”功能：一种定时开启的主题聊天室。站长可以提前预告主题（如：“今晚8点：讨论Java虚拟线程”），到点后用户涌入特定聊天室进行集中讨论，结束后讨论内容可自动整理为一篇精华帖子。

声望与成就系统：用户发表文章、获得点赞、评论等可获得积分和勋章。高声望用户可获得特殊标识或权限，激发活跃度。

高质量的实时协同：基于现有轮询技术，实现“实时共同编辑” 的草稿箱。允许用户邀请他人一同撰写某篇文章，虽然技术挑战大，但极具爆点。

1.1.3提升用户体验与自动化

自动化摘要与AI标签：集成开源AI大模型（如ChatGLM、Llama的本地API），在用户发布文章后自动生成摘要和推荐标签，减轻用户负担。

内嵌式小工具：支持在文章中嵌入投票、任务列表、思维导图等小型交互组件，丰富内容形式。

全站智能搜索：不仅搜索文章标题和内容，还能搜索到评论、聊天记录中的高质量信息。

1.2商业化模式

1.2.1开源核心版 + 付费托管版

开源版 (Community Edition)：

在Gitee/Github上完全开源，使用GPL/AGPL协议（保护开源精神）。

功能齐全，包含上述所有创新功能，吸引开发者、技术爱好者、小团队使用和贡献代码。

盈利点：树立品牌，建立社区，为付费版引流。

付费托管版 (Hosted Pro Edition)：

提供SaaS（软件即服务） 模式。用户无需自己部署服务器，注册账号即可使用。

提供更丰富的主题模板、更大容量的存储和附件上传、更强大的AI功能、专属技术支持、数据定期备份等增值服务。

定价策略：按月/年订阅，提供个人版、团队版、企业版不同档位。

1.2.2其他变现渠道

应用市场：建立一个主题和插件市场。开发者可以为其开发付费主题或功能插件，平台从中抽取佣金。

企业级定制部署服务：有些企业希望私有化部署，并需要特定功能定制。你可以提供有偿的技术支持和定制开发服务。

捐赠渠道：在开源项目首页明确提供支付宝、微信支付、Open Collective等捐赠渠道，接受社区的支持。


二、Functional Analysis

2.1核心模块

2.1.1知识库/博客系统(核心)

文章管理：富文本编辑（支持Markdown为佳）、文章创建、编辑、删除、分类、标签。

内容展示：博客首页、文章详情页、按分类/标签筛选、文章搜索。

评论系统：用户可对文章发表评论，支持盖楼回复。

2.1.2实时聊天室(特色功能)

公共聊天室：所有登录用户可进行实时文字交流。

在线用户列表：显示当前在线的用户。

2.1.3用户系统(基础)

用户注册、登录、注销。

个人资料修改、头像上传。

权限区分（普通用户、管理员）。

2.2扩展功能(增强实用性)

文章收藏与点赞：用户可收藏喜欢的文章，为文章点赞。

实时通知：当用户收到回复或被@时，页面右上角出现实时小铃铛提示。

私信功能：用户之间可以发送一对一私信。

知识图谱：通过标签自动关联相关文章，形成知识网络。


三、Nonfunctional Analysis

3.1性能 (Performance)

首页加载时间 < 2秒。
文章列表页响应时间 < 1秒。
AJAX轮询间隔设置合理（如3-5秒），避免服务器压力过大。

3.2安全性 (Security)

用户密码需加盐哈希（SHA-256）存储，绝不明文。
所有用户输入进行过滤和转义，有效防御XSS攻击。
使用Prepared Statement，彻底防御SQL注入。
文件上传目录限制脚本执行权限，防止上传漏洞。

3.3可用性 (Usability)

界面简洁直观，遵循常见Web应用交互习惯。
提供清晰的操作反馈（如成功提示、错误信息）。

3.4可靠性 (Reliability)

保证核心功能（发文、评论、聊天）的可用性。
数据库需进行定期备份。
